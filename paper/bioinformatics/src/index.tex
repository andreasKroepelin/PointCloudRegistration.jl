\section{Old}
This package addresses researchers and practioners within structural
bioinformatics and beyond who work with point cloud data.
Point clouds representing biological macromolecules were a prime consideration
during the development but no biological features are specifically assumed.
This also means that no surface or normal information is required or used.

The general setting where this package is applicable is the following:
Given two weighted $d$-dimensional point clouds,
a \emph{target} $X$ with points $\bm{x}_1, \dots, \bm{x}_I \in \mathbb{R}^d$
and weights $p_1, \dots, p_I$
as well as
a \emph{source} $Y$ with points $\bm{y}_1, \dots, \bm{y}_J \in \mathbb{R}^d$
and weights $q_1, \dots, q_J$,
we want to find a \emph{rigid} (rotation and translation) or \emph{non-rigid
transformation} (more complex displacement) that maps the source onto the target
in some optimal way.


\section{Rigid registration}

Formally, the problem of rigid registration can be stated as follows:
\begin{align*}
  \min_{T \in \operatorname{SE}(d)}
  \sum_{i = 1}^I
  \sum_{j = 1}^J
  c_{i j}
  p_i q_j
  \cdot
  \rho\left(
  \lVert
  \bm{x}_i - T(\bm{y}_j)
  \rVert
  \right)
\end{align*}
where $c_{i j}$ expresses the strength of the correspondence between the $i$-th
point of the target and the $j$-th point of the source and $\rho$ is some cost
function.

\subsection{Known correspondences}
When superimposing biomolecluar structures, it is often known which point in the
source corresponds to which point in the target, e.g. from sequence alignments.
In this case, we have
\begin{align*}
c_{i j} = \begin{cases}
  1 & \text{ if } i = j \\
  0 & \text{ else } \\
\end{cases}
\end{align*}
which implies the source and target having equal size, i.e. $I = J$.

\subsubsection{RMSD}
In the simplest case, we can trust these correspondences and also assume the
difference between source and target to be solely due to the rigid
transformation.
We then minimize the \emph{root mean square displacement} (RMSD), i.e.
$\rho(r) = r^2$, using the \emph{Kabsch} algorithm, which finds the global
optimum in a closed form by means of a singular value decomposition.

\subsubsection{Mean Absolute Displacement}
Often, however, some correspondences might be spurious or the displacement
between some source and target points cannot be explained by a rigid
transformation alone.
In the context of minimizing the RMSD, these can be considered outliers and they
potentially confound the optimal transformation.

The cost functon $\rho(r) = r$ is less sensitive to outliers but the resulting
optimisation problem does not have a closed form solution.
Instead, we use an iterative procedure.
The implemented algorithm is a \emph{majorization minimization} scheme where
we majorize the original objective function by a quadratic one and then
minimize the latter by the Kabsch algorithm to find an improved candidate for
the global optimum.

\subsubsection{Geman-McClure cost}
Alternatively, outliers can be mitigated by limiting their influence, which can
be done by using the \emph{Geman-McClure} cost function
$\rho(r) = r^2 / (2\sigma^2 + r^2)$ with some scale parameter $\sigma$.
It behaves like $r^2$ for small $r$ but flattens out to $1$
for large $r$, where $\sigma$ determines what small and large means.

Since the optimization problem becomes non-convex, the majorization minimization
iterations are not guaranteed to find the global optimum.
See Section \ref{sec:opt-strats} for strategies to avoid local optima.

\subsection{Unknown correspondences}
For general point clouds or when no sequence information matching the structure
is available, we cannot rely on known correspondences.
This forces us to either treat every correspondence as equally likely or
estimate the correspondences on the fly.

\subsubsection{Kernel correlation}
The package implements the method proposed in \cite{our-kc-paper}
where we have $c_{i j} \equiv 1$ and $\rho(r) = - \exp(-r^2 / 2 \sigma^2)$ with
a scale parameter $\sigma$.

Similar to the Geman-McClure based registration, we perform non-convex
majorization minimization with optimization strategies outlined in Section
\ref{sec:opt-strats}.
We also make use of precomputation that allows the runtime of the
implementation to be linear in the sizes of the point clouds even if
conceptually all pairs of points are considered in the objective function.

\subsubsection{Iterative Closest Point}
Due to its widespread adoption, we also implemented the \emph{Iterative Closest
Point} method in this package.
The cost function is simply $\rho(r) = r^2$ again, but now the correspondences
are updated iteratively.
That is, if we have a candidate transformation $\hat{T}$, we set
\begin{align*}
  c_{i j} = \begin{cases}
    1 & \text{ if }
      i = \arg\min_{i'} \lVert \bm{x}_{i'} - \hat{T}(\bm{y}_j) \rVert
      \text{ and }
      \lVert \bm{x}_i - \hat{T}(\bm{y}_j) \rVert \leq D \\
    0 & \text{ else}
  \end{cases}
\end{align*}
with some cut off distance $D$.
We use kd-trees to efficiently find the closest target point for each source
point.
An improved transformation is again found using the Kabsch algorithm.


\subsection{Optimization strategies}
\label{sec:opt-strats}

Optimizing the Geman-McClure cost and the kernel correlation, as well as the
Iterative Closest Point method are all non-convex optimization problems with
multiple local optima.
We employ several strategies to find the global optimum.

\subsubsection{Simulated Annealing}
The Geman-McClure cost and the kernel correlation both depend on a scale
parameter $\sigma$ that determines the smoothness of the overall objective
function.
By optimizing with a larger $\sigma$ first and then decreasing its value towards
the desired one, we can make narrower optima appear later and guide the
iteration towards the global optimum.
As an initial value for $\sigma$, we chose the square root of the largest
eigenvalue of the covariance matrix of the target by default.
It is an efficiently computable heuristic for the diameter of the point cloud.

\subsubsection{Stochastic sums}
It turns out that the relevant computational steps in the individual methods all
have the form $\sum_{j = 1}^J q_j A(j)$ with the weights of the source point
cloud $q_1, \dots, q_J$ and some quantity $A$ that depends on $j$.
We can thus approximate these sums by repeatedly sampling the index $j$
according to the categorical distribution defined by the weights $q_j$ and then
computing the sample average of the corresponding quantities $A(j)$.

Similar to the technique of stochastic gradient descent popular in deep
learning, this avoids local optima because only optima that are true for many
subsampled parts of the source have an effect on the iteration.

\subsubsection{Multiple restarts}
All three discussed methods are sensitive to the initial transformation
candidate.
We thus perform multiple restarts with randomly chosen initial transformations.
For this, we draw a rotation $\bm{R}$ uniformly from the rotation group
$\operatorname{SO}(d)$, then pick a target point $\bm{x}_i$ and a source point
$\bm{y}_j$ and set the initial transformation to $\bm{x}_i - \bm{R} \bm{y}_j$.
This ensures that the initial transformation produces some overlap of the
two point clouds.
Additionally, we try the identity transformation as an intial guess to never
miss in case the point clouds are already superimposed.

All these strategies are configurable by users of this package, that is the
set of annealing levels, how many samples to use for the stochastic sums, and
how many restarts to perform.
Default values are chosen such that the global optimum can be expected to be
found in at least 99\,\% of cases with as few restarts as possible, according
to experiments.


\section{Non-rigid registration}

To adress more finegrained differences between the source and target point
cloud, the package also offers functions to perform non-rigid registration.
Here, the task is to find new source points $\hat{\bm{y}}_1, ..., \hat{\bm{y}}_J
\in \mathbb{R}^d$ that establish a trade-off between matching the target and
bearing a resemblance to the source.
Different approaches to non-rigid registration quantify these two objectives
differently.

\subsection{Coherent Point Drift}
Several methods estimate soft correspondences between source and target during
the non-rigid registration.
In an expectation-maximization fashion, this estimation is alternated with
finding displacement
We opted for implementing the \emph{Coherent Point Drift} method.
This estimates a displacement vector $\bm{v}_j \in \mathbb{R}^d$ for every
point in the source cloud such that the displaced source matches the target
and that $\bm{v}_j$ and $\bm{v}_k$ are similar whenever $\bm{y}_j$ and
$\bm{y}_k$ are close.

\section{Thinning point clouds}

Especially when the goal is to perform rigid registration, large point clouds
provide much more data than is nececessary to estimate the (in three dimensions:
six) parameters describing the rigid transformation.
Since the runtime of the registration methods depends on the number of points,
it can be beneficial to perform \emph{thinning} where we represent the same
point cloud by fewer points.

The package implements two approaches to thinning, depending on if the user has
a number of points or a resolution in mind:
For the former, the thinning performs a standard $k$-means clustering.
For the latter, Dirichlet process means clustering allows finding points that
have a given minimal distance to each other.
Both methods respect the weights of the point cloud and produce an appropriately
weighted point cloud in turn.

\section{Implementation notes}

\subsection{Performance considerations}

The just-in-time compilation model of Julia allows the implementation to
optimally adapt to the dimensionality of the point cloud without sacrificing
user or developer experience.
The generated machine code exploits the statically known sizes of vectors and
matrices representing points, means, covariances, etc., avoiding dynamic memory
allocations, inlining computations, and using special implementations of certain
functions depending on the dimension.

Certain registration methods, like optimizing the kernel correlation and
Coherent Point Drift, allow for precomputing significant parts of their workload
that depend only on either the source or the target.
These precomputations are available as extra functions in the package so that
users can reuse the precomputed data if possible.
For example, when rigidly registering many sources to the same target in terms
of the kernel correlation, the computationally heavy precomputation for the
target can be done once and then registering the individual sources is greatly
accelerated.

\subsection{Interoperability}

Large parts of this package can be applied to point clouds where the coordinates
have physical units, represented without run time overhead by Unitful.jl.
Where necessary and possible, the code was adapted minimally to account for this
use case.

Via the Python package juliacall, this package can be used from Python as well.
It is specifically tested to make sure this integration works properly.

\subsection{Superimposing proteins based on sequence alignment}
As we have seen in the previous section, minimizing the RMSD is faster than
minimizing the Geman-McClure cost.
However, being more robust against outliers can help with macromolecular
structures that differ by large-scale movement of entire domains.
We demonstrate this using PDB structures of the $\text{Ca}^{2+}$-ATPase that
conincide in their sequence but differ structurally.

The fifteen point clouds were pairwise rigidly superimposed by minimizing the
RMSD and the Geman-McClure cost (GMC).
In Figure \ref{fig:pdb-distances}, the heatmaps show the distance of
corresponding atoms after superimposing for each pair of point clouds and both
methods.
Note how for the RMSD the distances are spread rather evenly without clear
patterns.
For the GMC, on the other hand, we see very low and very high distances that
tend to group together for consecutive stretches of the proteins that are
somewhat stable over different pairs.

\begin{figure}[h]
\centering
\includegraphics[width=\linewidth]{img/pdb-heatmaps.pdf}
\caption{
    For each pair of point clouds representing different $\text{Ca}^{2+}$-ATPase
    structures (indicated by their PDB identifiers), the heatmaps show the
    color-coded distances of corresponding $\text{C}\alpha$-atoms along the
    protein sequence after rigidly registering the pair by minimizing either the
    RMSD or the Geman-McClure cost (GMC).
}\label{fig:pdb-distances}

This means that optimizing the RMSD leads to a ``compromise'' fit while the GMC
matches a ``core'' and ignores heavily displaced domains.
This is arguably more useful for the biological application.

\subsection{Fitting rRNAs into ribosomal electron microscopy map}
Next, let us demonstrate working with point clouds and density maps.
To this end, we fit two pointclouds representing the 23S- and 16S-rRNA (PDB
identifiers 9o17\_26 and 9o17\_1) into a density map representing the whole
bacterial ribosome (EMDB identifier 49998, \cite{ribosome}).

The density map has to be converted into a point cloud, which is achieved by
first placing a point at every voxel center with the voxel's value as its
weight and then thinning the point cloud to a resolution of 10\,Å.
Points with a weight below a threshold are removed.
For the rRNAs, we collect their 3'-C atom coordinates with uniform weights and
apply a random rigid transformation to them as they are already positioned at
the correct pose in the PDB.

Using the larger 23S-rRNA as the source and the full ribosome as the target, we
now rigidly register the rRNA onto the ribosome by maximizing the kernel
correlation.
Success can be validated by comparing the registered rRNA coordinates to the
original PDB coordinates (RMSD $4.2\,$Å).

Next, we reduce the target point cloud by removing all its points that are
within 10\,Å of the fitted 23S-rRNA (we have ``used'' these now).
Subsequently, we register the smaller 16S-rRNA onto the remaining target via
the kernel correlation.
Again, we closely match the original PDB coordinates (RMSD $2.6\,$Å).

\subsection{Aligning micrographs}
By turning images into weighted two dimensional point clouds, we can apply
point cloud registration to image registration as well.
We demonstrate that using micrographs of mitochondria from the BioTISR data set
by \cite{biotisr-data}.
For the 20 time-lapse images, 19 rigid 2D-transformations
$T_2, \ldots, T_{20} \in \operatorname{SE}(2)$ were drawn randomly and the
images were transformed by the respective transformation.
To keep a global reference frame, we chose $T_1 = \operatorname{id}$.
In this modified data set, the images now differed in (artificial) rigid
transformations and (actual) movements of the depicted objects.
The transformed images were then turned into point clouds by placing a point at
every pixel with the pixel's intensity as the weight.
For computational efficiency, points with low weight (below the 99.5\,\% weight
quantile) were dropped and the point clouds were thinned to a nearest neighbor
distance of 10 pixels.

To perform the registration, we set the first point cloud as the target and then
maximized the kernel correlation of every point cloud with it, obtaining
transformations $T'_1, \ldots, T'_{20} \in \operatorname{SE}(2)$.
For a successful registration, we have $T'_i \circ T_i \approx \operatorname{id}$,
for every $i = 1, \ldots, 20$.
That is, we can analyze the success by observing the ``residual'' transformation
$T'_i \circ T_i$, see Figure \ref{fig:biotisr-overlay}.
Note how the original images match the ones transformed by this residual
transformation very closely.


\begin{figure}[h]
\centering
\includegraphics[width=\linewidth]{img/biotisr.png}
\caption{
    Mitochondria images from the BioTISR data set.
    Each panel shows the same section for one of twenty time-lapse images.
    The original image with index $i$ is displayed in the green channel and
    itself transformed by the ``residual'' transformation $T'_i \circ T_i$
    displayed in the blue channel.
    Bright green or blue regions indicate poor registration whereas cyan regions
    signal a good overlap of the images.
